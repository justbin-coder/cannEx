# CannEx 开发维护指南

> 面向**知识库维护者 / 开发者**：建/更新知识库、升级外部依赖、验证产物。
> 只讲"建库与维护"，"把服务跑起来"见 [部署指南](部署指南.md)，全局心智模型见 [项目架构与配置](项目架构与配置.md)。
> 命令默认从**仓库根目录** `<repo-root>` 执行。

---

## 0. 知识库构建总览

CannEx 有**双知识源**，离线构建、运行时只读：

```
build/docs.yaml  ─┐                      ┌─► workspace/docs/<id>.json   (文档树, 入 git)
                  ├─ sync_sources.py ──► raw/ ─┤
build/repos.yaml ─┘                      └─► raw/repos/<name>/.codegraph/ (代码图谱, 不入 git)
                                              workspace/repos/<name>/*.yaml (策展, 入 git)
   配置(配方)            拉素材              build_docs.py / build_repos.py        产物
```

**两个前置（绕不开）**：① 建文档树要 **LLM API 凭据**（调 DeepSeek/Anthropic 网关）；② 能访问原始素材（PDF + 算子仓 git 地址，已写在两个 yaml）。

---

## 1. 一次性：装外部依赖（PageIndex + CodeGraph）

仓库不 vendor 外部工具源码，只收纳"重建配方"在 `3rd/`（详见 `3rd/README.md`）。新机器先跑两个安装脚本：

```bash
# PageIndex（建文档树用，是打过 7 处补丁的魔改版）
bash 3rd/pageindex/setup.sh
#  → clone 上游@锁定commit → 打 cannex.patch → 建 venv → 装依赖
#  → 装到 3rd/pageindex/PageIndex/（已 gitignore）
#  完成后编辑 3rd/pageindex/PageIndex/.env 填你的 LLM key

# CodeGraph（建代码图谱 + 运行时查询都用，锁定 0.9.6）
bash 3rd/codegraph/setup.sh
```

> ⚠️ **已知坑（必读）**：`build_docs.py:50` 当前**写死** PageIndex 路径为 `~/project/CANN/PageIndex`，
> **不读** `3rd/README.md` 说的 `CANNEX_PAGEINDEX_DIR`。所以照 3rd 脚本装到 `3rd/pageindex/PageIndex`
> 后，建树会找不到。**临时解法**（二选一）：
> ```bash
> # A. 软链到代码期望的位置
> ln -s "$PWD/3rd/pageindex/PageIndex" ~/project/CANN/PageIndex
> # B. 直接把 PageIndex 装在 ~/project/CANN/PageIndex（手工 clone+打补丁）
> ```
> 根治办法见文末「待修项」。

## 2. 操作指导：添加 / 更新素材源

素材清单是"配方"，改它再拉取：

```bash
# 1. 编辑配置，新增或开关条目（enabled: true/false）
#    build/docs.yaml   — 文档（PDF）；新增需把 PDF 手放到 raw/docs/ 下对应 local_path
#    build/repos.yaml  — 算子仓（git）；会自动 clone/fetch

# 2. 拉取（repo 自动 git clone/fetch；doc 仅检查 PDF 是否就位，不自动下载）
python3 build/sync_sources.py            # 加 --dry-run 只看变更不动手
```

`docs.yaml` 关键字段：`category`（短名，检索用）、`build_mode`（`pageindex` 默认 / `api_ref` 零-LLM）、`doc_description`（LLM 选文档的依据）、`enabled`。
`repos.yaml` 关键字段：`url` / `ref` / `local_path` / `enabled`。

## 3. 操作指导：文档建树（build_docs.py）

把 PDF 变成 LLM 可推理的结构化文档树（PageIndex）。**增量**：`_meta.json` 里已存在同 `doc_name` 的跳过。

```bash
# 前置：§1 已装好 PageIndex 且 .env 填了 LLM key
python3 build/build_docs.py

# 大文档耗时长，建议后台跑并落日志：
nohup python3 -u build/build_docs.py > logs/build_docs.log 2>&1 &
tail -f logs/build_docs.log
```

两种构建模式（按 `docs.yaml` 的 `build_mode` 自动分发）：
- **`pageindex`（默认）**：调 PageIndex + LLM 建 ToC 推理树，**烧 token**，适合叙事类文档。
- **`api_ref`**：PyMuPDF 直提，**零 LLM、快、免费**，适合接口参考类（如算子 API 参考）。

产物：`workspace/docs/<doc_id>.json` + 自动登记到 `workspace/_meta.json`。

**排错**：失败先看日志；PageIndex 对上游 DeepSeek 断连通常**自愈重试**可恢复；KeyError/空响应类问题多已被 `3rd/pageindex/cannex.patch` 兜住，仍报错则复审补丁（见 `CLAUDE.md §六`）。

## 4. 操作指导：代码仓 Graph 创建（build_repos.py）

对算子仓建 CodeGraph 索引，支撑代码侧符号搜索/调用链/影响面。**增量**：已有 `.codegraph/` 的跳过。

```bash
# 前置：§1 已装 codegraph CLI；§2 已 sync 到 raw/repos/
python3 build/build_repos.py
#  对每个 enabled 仓：codegraph init → codegraph index（每仓可能几分钟）
```

产物：
- `raw/repos/<name>/.codegraph/`（图谱索引，~1GB 量级，**不入 git**）
- `workspace/repos/<name>/{repo_card,samples}.yaml`（仓元数据 + 样例标注；自动生成骨架，**人工精修后入 git**）

> `repo_card.yaml` / `samples.yaml` 是**人工策展层**（L0），建完后需人工补充"这个仓讲什么、哪些是好样例"。

## 6. 操作指导：月度全量更新

## 7. 升级外部依赖

**PageIndex（魔改版）**——pin 上游 + 打补丁，升级须复审补丁：
```bash
cd 3rd/pageindex/PageIndex
git fetch origin && git checkout <新上游commit>
git apply --3way ../cannex.patch          # 冲突手工解
git diff <新commit> -- pageindex/ > ../cannex.patch   # 解完重新导出补丁
# 同步更新 setup.sh 的 UPSTREAM_COMMIT、3rd/README 的 pin、CLAUDE.md §六 补丁表
```

**CodeGraph（原版 npm）**——改 `3rd/codegraph/setup.sh` 的 `PIN` 后重跑。最低版本 `0.9.4`。
