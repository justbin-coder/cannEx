# CannEx 部署指南

> 面向**部署/运维者**：把 CannEx webchat 跑起来、管账号、配登录。
> 只讲"运行"，不讲"建知识库"——后者见 [开发维护指南](开发维护指南.md)。
> 全局心智模型见 [项目架构与配置](项目架构与配置.md)。
> 下文命令默认从**仓库根目录**执行，记作 `<repo-root>`。

---

## 0. 三种部署形态怎么选

| 形态 | 命令入口 | 适用 | HTTPS |
|---|---|---|---|
| **裸跑（推荐内部试用）** | `bash deploy/run_local.sh` | Mac/Linux 单机、5–20 人内网 | 无（http://内网IP） |
| **Docker Compose** | `deploy/docker-compose.yaml` | 有公网 IP、要自动 HTTPS | Caddy 自动签 |
| **本地开发** | `chainlit run app.py -w` | 改代码、热重载 | 无 |

本指南主讲**裸跑**（最常用）。Docker 形态见 `deploy/README.md`。

---

## 1. 首次部署（裸跑，4 步）

```bash
# 1. 拉仓
git clone https://github.com/justbin-coder/cannEx.git && cd cannEx

# 2. 一键建环境（建 venv + 装依赖 + 生成 deploy/.env 含随机密钥 + 自检）
bash bootstrap.sh

# 3. 建第一个账号（密码登录模式必需，见 §3）
PFX="CANNEX_USERS_DB=$PWD/deploy/cannex.db PYTHONPATH=$PWD webchat/cannex_chat/.venv/bin/python3 deploy/seed_users.py"
eval "$PFX admin 你的强口令"

# 4. 启动
bash deploy/run_local.sh           # 默认 0.0.0.0:8080
```

打开 `http://<本机IP>:8080`，用 admin 账号登录。登录后在 UI 的 Settings 里填**自己的** LLM key（BYOK）。

> LLM key 不用在服务端配——每个用户在网页里填自己的（BYOK）。详见 [架构文档 §BYOK](项目架构与配置.md)。

---

## 2. 启动 / 重启 / 停止

```bash
bash deploy/run_local.sh            # 幂等：停旧进程 + 重启 + 日志落 logs/webchat.log
tail -f logs/webchat.log            # 看启动日志
pkill -f "chainlit run app.py"      # 仅停止
```

改端口：`CANNEX_PORT=9000 bash deploy/run_local.sh`

> 裸跑**不带 `-w`，改了后端代码必须重跑 `run_local.sh`** 才生效。

## 3. 账号管理

> ⚠️ 项目**无角色权限系统**——所有账号平权。"管理员"只是约定（指在服务器上跑 `seed_users.py` 的人），登录后大家功能完全一样。建"管理员账号"和"普通用户账号"是**同一条命令**。

统一前缀（从 `<repo-root>` 执行）：

```bash
PFX="CANNEX_USERS_DB=$PWD/deploy/cannex.db PYTHONPATH=$PWD webchat/cannex_chat/.venv/bin/python3 deploy/seed_users.py"
```

| 操作 | 命令 |
|---|---|
| 新增 / 改密（同名 upsert） | `eval "$PFX 张三 他的强口令"` |
| 批量新增（每行 `用户名 口令`） | `eval "$PFX --stdin" < users.txt` |
| 列出账号 | `eval "$PFX --list"` |
| 删除账号 | `eval "$PFX --delete 张三"` |

- 口令用 **bcrypt** 加密存储（`cost=12`），数据库里没有明文。
- **增删账号无需重启**——每次登录现查 SQLite，立即生效。
- 账号库文件：`deploy/cannex.db`（已 gitignore，记得单独备份）。

## 4. 登录模式切换（密码登录 ↔ 免登录）

由 `webchat/cannex_chat/.env` 里 `CANNEX_DISABLE_AUTH` 控制：

| 模式 | 配置 | 行为 |
|---|---|---|
| **密码登录**（默认/推荐） | 注释掉 `CANNEX_DISABLE_AUTH` | 需账号；每人 key 加密入库、**下次登录免重填**、按用户隔离 |
| **免登录** | `CANNEX_DISABLE_AUTH=1` | 任何人可进；key **只存会话内存、不落库**、刷新即丢；无访问控制 |

切换后 **`bash deploy/run_local.sh` 重启** 生效。

> 安全提醒：**免登录 + 服务端公用 key = 任何人都能白嫖你的额度**，切勿同时开。多人用一律走密码登录。

## 5. 部署须知（换服务器必看）

1. **密钥必须重新生成**：`bootstrap.sh` 会自动生成 `deploy/.env` 里的随机密钥；若手工部署，务必
   `openssl rand -hex 32` 生成新 `CHAINLIT_AUTH_SECRET` / `CANNEX_CONFIG_SECRET`，**不要复用任何示例值**。
2. **文档侧开箱即用**：`workspace/docs/` 随 git 而来，clone 即可问文档。
3. **代码侧需额外准备**：算子源码 `raw/repos/` 与图谱 `.codegraph/` **不在 git**，要代码侧检索（调用链/影响面）得另传或重建，见 [开发维护指南](开发维护指南.md)。缺失时代码侧 API 优雅降级返回错误信封，不影响文档侧与服务启动。
4. **Docker/HTTPS**：换公网 IP 要改 `deploy/Caddyfile` 里的 nip.io 域名，详见 `deploy/README.md`。

## 6. 常见故障

| 症状 | 排查 |
|---|---|
| 启动报 `CHAINLIT_AUTH_SECRET 未设置` | 没跑 `bootstrap.sh` 或 `deploy/.env` 缺密钥；见 §1 第 2 步 |
| 登录页能开但密码不对 | 账号没建或密码错；`eval "$PFX --list"` 查，必要时 upsert 改密 |
| 日志 `Authentication failed in websocket connect` | 开启鉴权后旧标签页拿失效连接重连，**正常**，重新登录即消失 |
| 发问报 `401 / invalid_api_key` | 用户没在 UI 填 key，或填错；让其在 Settings 重填 |
| 工具调用报 `workspace/_meta.json` 找不到 | clone 不完整或 `CANNEX_ROOT` 指错；确认在仓库根启动 |
| 代码侧报 `codegraph CLI not found` | 没装 codegraph；`bash 3rd/codegraph/setup.sh` |
