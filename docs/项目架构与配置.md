## 1. 一句话定位

CannEx = 面向 Ascend C 算子开发者的 **AI 学习助手**，双知识源（官方**文档** + 官方**算子代码**），所有回答 grounded 在真实文档/代码，引用可追溯。

## 2. 架构总览

```
┌─────────────────────────── 运行时（在线，只读 workspace/）────────────────────────────┐
│                                                                                        │
│   浏览器 ──► Chainlit (webchat/cannex_chat/app.py)                                      │
│               │  ├─ auth.py        密码登录（bcrypt + SQLite）                          │
│               │  ├─ agent/loop.py  Agent 循环（Anthropic tool_use）                     │
│               │  └─ worker/        子进程，跑检索工具                                    │
│               ▼                                                                         │
│           lib/cannex_knowledge/   ◄── 知识检索层（双范式）                              │
│               ├─ retriever_doc.py  文档侧：PageIndex 推理范式（无 score/排序）          │
│               └─ retriever_repo.py 代码侧：CodeGraph（FTS5+图距离，透传 score）         │
│                                                                                        │
└────────────────────────────────────────────────────────────────────────────────────┘
        ▲ 读                                                          ▲ 读（代码侧调 CLI）
        │                                                            │
   workspace/docs/*.json (文档树)                          raw/repos/<name>/.codegraph/ (图谱)
        ▲ 建                                                          ▲ 建
┌───────┴──────────────────────── 离线构建（维护者，build/）──────────┴───────────────┐
│   sync_sources.py → build_docs.py(PageIndex/零LLM) / build_repos.py(CodeGraph)        │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

**两阶段路线**：Phase 1 = Claude Code 内的 `ascend-c` Skill；Phase 2 = 独立 Web 应用（Chainlit），即当前部署形态。知识层 `lib/` 两阶段共用。

## 5. 环境变量全集

**密钥（必配，部署侧）**
| 变量 | 默认 | 说明 |
|---|---|---|
| `CHAINLIT_AUTH_SECRET` | 无（**必填**） | 登录会话 JWT 签名密钥；换掉注销所有在线用户 |
| `CANNEX_CONFIG_SECRET` | 回退 `CHAINLIT_AUTH_SECRET` | 用户 BYOK key 的加密密钥；换掉已存 key 失效需重填 |

**运行控制**
| 变量 | 默认 | 说明 |
|---|---|---|
| `CANNEX_DISABLE_AUTH` | 未设=密码登录 | `=1` 切免登录（key 不落库、无访问控制） |
| `CANNEX_USERS_DB` | `/data/cannex.db`（裸跑由 run_local 设为 `deploy/cannex.db`） | 账号 + BYOK 配置库 |
| `CANNEX_PORT` | `8080`（裸跑） | 监听端口 |
| `CANNEX_ROOT` | 自动推导 | 项目根；仅从仓外启动时才需显式设 |
| `CANNEX_LOGS_DIR` | `<root>/logs` | 日志目录 |
| `CANNEX_MODEL` | `claude-sonnet-4-6` | 默认推理模型 |
| `CANNEX_SYSTEM_PROMPT_PATH` | 内置 | 覆盖教学 system prompt |
| `CANNEX_CODEGRAPH_BIN` | 自动探测 | 显式指定 codegraph 二进制（worker 找不到时用） |

**LLM 调优旋钮**
| 变量 | 默认 | 说明 |
|---|---|---|
| `CANNEX_MAX_TOKENS` | `8192` | 单次回复最大 token |
| `CANNEX_LLM_TIMEOUT` | `120` | LLM 连接/读取超时（秒） |
| `CANNEX_STREAM_TIMEOUT` | `180` | 单次流式总时长上限（秒） |
| `CANNEX_STREAM_MAX_CHARS` | `200000` | 单次流式累计输出字符上限 |

**当前未消费（保留位）**：`ANTHROPIC_API_KEY` / `ANTHROPIC_BASE_URL` —— 走 BYOK，chat 路径不读，填了也不生效。

## 7. BYOK 与多用户隔离（安全模型）

- **BYOK**（Bring Your Own Key）：LLM 费用与凭据归用户自己，服务端不垫 key。用户登录后在 UI Settings 填自己的 key。
- **存储与隔离**：key 经 `CANNEX_CONFIG_SECRET` 派生的 Fernet 加密，按 `username` 存 SQLite。普通用户**互相看不到**（受 `WHERE username=?` + 登录鉴权隔离）。
- **加密保护的是"DB 文件被偷"**，不是用户间隔离；持有 `CANNEX_CONFIG_SECRET` 的服务器管理员技术上可解密全部——这是 BYOK 的信任边界。
- **免登录模式下**无 username → key 仅存会话内存、不落库、不跨用户泄漏，但刷新即丢、且无访问控制。

## 8. 关键技术决策（速查，详见 CLAUDE.md §五/§九）

| 维度 | 选择 |
|---|---|
| 文档检索范式 | PageIndex **推理式**（LLM 在 ToC 树上推理，工具层**不打分/不排序**） |
| 代码检索范式 | CodeGraph（FTS5+图距离），lib 不二次排序，**透传 score** 给 LLM 参考 |
| 教学侧 LLM | Claude Sonnet 4.6（BYOK） |
| 文档建树 LLM | DeepSeek（中文友好、便宜） |
| webchat 集成知识层 | subprocess 调 CLI，零侵入解耦 |

> 红线：文档侧不得引入 `search/rank/score/top_k`；代码侧不得在 lib 内裸 SQL/二次排序。详见 `CLAUDE.md §九`。
