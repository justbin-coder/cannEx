# CannEx — 开发者需求分析

> 来源：CANN 开发者真实反馈 + 学习旅程痛点推导
> 更新：2026-04-29

---

## 一、开发者反馈原声（分类整理）

### 1.1 代码样例不足

- "代码示例不够丰富"
- "在线实验可用的实验案例太少了"
- "CANN sample 教程不明确，示例代码无法及时改动到代码里"
- "已有的算子仓库成果物，介绍较难理解，缺少直观描述，理解门槛较高"

### 1.2 文档难以理解

- "专业术语几乎不会立刻解释，对初学者简直是噩梦"
- "cann 规格参数配置，文档不够小白，入门者难懂"
- "章节和大纲分布、内容不合理"

### 1.3 学习路径缺失

- "学习路径设计得不够清晰，知识点衔接有点断层，从基础理论到实操的过渡不顺畅，也没有分阶段的进阶规划"
- "基础课程上来就聊 AscendC、CANN，对于跨行的同学来说，如何从零基础丝滑过渡，这一步没打通"

### 1.4 版本/硬件混杂

- "Ascend 910B1、910A、910B2 各类文档混杂，无法有效区分和对应，再叠加不同的 CANN 版本、不同的 Torch 版本，根本无法有效使用"

### 1.5 排障支持不足

- "报错解决的 FAQ 较少，故障案例不够丰富"
- "环境配置完一跑代码就出问题，没法顺利完成实操练习"

### 1.6 移动端体验（超出 CannEx 范围）

- "移动端适配差、搜索功能需要优化"
- "看直播课完全找不到入口"
- "没有 iOS 版本的 APP"

## 二、需求提炼

| ID | 需求 | 来源痛点 | CannEx 覆盖度 |
|----|------|---------|-------------|
| N1 | 结构化学习路径：知识按依赖关系编排，前后衔接无断层 | 1.3 | 完全覆盖 |
| N2 | 术语即时解释：专业术语内联解释，用类比降低理解门槛 | 1.2 | 完全覆盖 |
| N3 | 丰富的代码样例库：按算子类型/难度组织，完整可运行 | 1.1 | 完全覆盖 |
| N4 | 故障诊断 + 排障指南：报错码解读、精度排查、常见故障案例 | 1.5 | 完全覆盖 |
| N5 | 代码教学注释：每个样例带逐行注释 + 数据流图 | 1.1 | 完全覆盖 |
| N6 | 前置知识桥接：为跨行/零基础开发者提供认知过渡 | 1.3 | 完全覆盖 |
| N7 | 版本/硬件适配标注：知识页明确标注适用硬件型号 + CANN 版本 | 1.4 | 部分覆盖（Phase 2 RAG 补齐全量组合查询） |
| N8 | 实验环境可用性：环境配置稳定，代码可直接运行 | 1.5 | 不覆盖（需要真实硬件/云环境支持） |
| N9 | 移动端适配 | 1.6 | 不覆盖（平台产品问题） |

## 三、需求到功能映射

```
N1 结构化学习路径    ──→  :learn（learning-paths.yaml）
N2 术语即时解释      ──→  :learn（Skill prompt 内置规则）
N3 代码样例库        ──→  :examples（knowledge/examples/）
N4 故障诊断          ──→  :pitfalls（诊断模式 + 预警模式）
N5 代码教学注释      ──→  :examples（样例模板规范）
N6 前置知识桥接      ──→  :learn（persona.md 桥接策略）
N7 版本/硬件标注     ──→  knowledge 页 applies_to 字段 + Phase 2 RAG
```
